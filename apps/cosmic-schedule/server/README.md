# 家庭同步服务器

该服务器提供与最新客户端一致的 revision 同步协议、冲突检测、原子替换和历史备份。每个家庭独立部署一个实例；服务器状态不会按账号分库，所有已配置账号访问同一份家庭计划。

## 运行

需要 Node.js 22.13 或更高版本，建议 Node.js 24。在产品目录复制 `.env.example` 为 `.env`，填写编辑账号与密码，并保留 `VITE_SYNC_ENDPOINT=/api/state`。Vite 在构建时读取该同步地址，`npm start` 读取同一份 `.env` 中的服务器配置。

```sh
npm ci
npm run build
npm start
```

启动前必须在 `.env` 或部署环境中设置以下变量；编辑账号必填，只读账号可留空：

| 环境变量 | 用途 |
| --- | --- |
| `PLANNER_USERNAME` | 可编辑账号的用户名 |
| `PLANNER_PASSWORD` | 可编辑账号的密码 |
| `PLANNER_VIEWER_USERNAME` | 可选的只读账号用户名 |
| `PLANNER_VIEWER_PASSWORD` | 只读账号密码，必须和用户名同时配置 |
| `PORT` | 本机端口，示例 `.env` 使用 `5180`；未指定时为 `3004` |
| `PLANNER_DATA_DIR` | 可选的持久化目录，默认产品目录下的 `data/` |

账号没有默认值；缺失、空值或只配置一半只读账号会阻止启动。用户名不能包含冒号或换行，用户名和密码均不能包含换行；编辑与只读用户名必须不同。凭证由部署者自行设置并保存在部署环境中，不要提交到仓库。

按示例配置打开 `http://127.0.0.1:5180/`（修改端口后使用自己的地址），浏览器会要求输入账号密码。页面、资源、健康检查和 `/api/state` 都先进行 Basic 认证；只读账号可读取计划，写入会返回 `403`。客户端与 API 应从同一网址访问。服务器不信任外部邮箱头或未经验证的 JWT。

服务器只监听 `127.0.0.1`。需要跨设备访问时，在其前方配置 HTTPS 反向代理并转发 Authorization 请求头；不要通过公网明文 HTTP 传输 Basic 凭证。静态 GitHub Pages 本身不运行这个服务器。

## 数据与备份

状态保存在 `planner-state.json` 中。写入必须携带当前 revision；过期 revision 返回 `409`，客户端按最新同步协议处理冲突。只接受协议 `2`；旧客户端写入返回 `426`。

每次成功保存先写临时文件、生成备份，再通过重命名替换当前文件；备份失败不会推进当前文件或内存 revision。`backups/revisions/` 保留每个 revision，`backups/` 另外保留每天首次写入的备份。服务器启动时若当前状态损坏会报错停止，避免覆盖原始记录。

数据目录中的文件属于实际部署者的私人数据。`data/` 已被仓库忽略；如配置其他目录，也请在部署环境独立保存和备份，勿放入公开源码。历史备份不会自动清理，部署者可按自己的保留需求管理空间。

更新源码后重新构建并重启服务器即可，保留原有数据目录。程序错误输出到启动终端；存储配额、文件权限或磁盘写入失败时，客户端保留待同步修改并提示等待同步。
